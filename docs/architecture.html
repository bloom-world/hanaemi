04

主な処理の流れ

会員登録・ログイン

  1. アプリでメール、Google、Apple のいずれかを選ぶ
  2. Authentication が本人確認（Google / Apple とは各社の仕組みで連携）
  3. メール登録の場合、独自ドメインから確認メールを送信
  4. 初回はプロフィールを Firestore に保存

今日の状態とトリニティ％

  1. アプリで今日の状態・設問の回答を Firestore に保存
  2. 保存をきっかけに Cloud Functions が％を計算
  3. 結果を Firestore に書き戻し、アプリのホームに反映

計算をサーバー側に置くことで、アプリを更新せずにロジックを調整できる

通知

  1. アラームは端末内で設定（ネイティブ機能。通信不要）
  2. リマインドや曇りアラートは Cloud Functions の定期処理で判定
  3. FCM から送信し、iOS は APNs 経由で届く

セルフワークの再生

  1. アプリが Firestore からセルフワークの一覧を取得
  2. 音声・画像を Cloud Storage から取得（または同梱）
  3. 再生中の音声はネイティブ機能で制御（マナーモード・イヤホン）
  4. 完了・評価を Firestore に記録

運営の管理画面

  1. 運営メンバーがブラウザで管理画面（Hosting）を開く
  2. Authentication でログインし、運営メンバーの権限を確認
  3. 設問やセルフワーク、お知らせを Firestore で編集

退会

  1. アプリの退会操作で Cloud Functions を呼び出す
  2. Firestore と Storage の本人データ、Authentication のアカウントを削除
  3. Web の公開ページに退会方法の案内を掲載（Google Play の要件）
